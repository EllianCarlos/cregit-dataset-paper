# srcML non-termination fix, 2026-10-09

The final report of the srcML fix subagent (local only; nothing pushed; no
GitHub fork). The main session saved it here. Scripts, logs and result files:
`~/s3-work/srcml-fix/` (not in git; `NOTES.md`, `timeout-coverage.tsv`,
`timing/`, `patches/`, `cregit-tests.log`). M = measured; I = inferred.

## Result

All 81 timeout exclusions of the census so far finish with the patched srcML,
in at most 1.02 s of CPU each. On 8,492 blobs, 8,454 token streams are
byte-identical to the old build and 38 differ: 22 never finished before, 12
correct the defect's own markup, and 4 are sqlite3.c copies (see below).

## Causes

1. **Adjacent string literals (lexer).** `char *s = "a""b";` (C, C++, ObjC).
   Old markup: `<literal>"a""</literal><name>b</name><literal>"…`, which swaps
   string and code for the rest of the file (M). Root cause:
   `src/parser/CommentTextLexer.g:235` at d38271916: the `'\042'` loop with
   `!skip_dquote_processing && (prevLA != '\\' || noescape)` takes a run of
   quotes as the closing quote. Fix: leave the loop when `mode == STRING_END`
   and `!noescape`, in C, C++ and ObjC only. On NSS certdata.c the swap makes the
   parser superlinear (100 KB 0.28 s, 200 KB 116.6 s, 400 KB+ over 900 s) (M).
2. **Function-name loop (parser).** `X template <class R> auto a;` (C++), and
   `namespace n{struct T&f(const struct S);}` parsed as C. Old: no output after
   10 s; new: 0.02 s (M). Root cause: `src/parser/srcMLParser.g:5612-5613`
   (statement_part, `{ inMode(MODE_FUNCTION_NAME) }? function_header[0]`):
   `function_header[0]` can match nothing, and `start()` calls it again for
   ever. Fix: when it consumes nothing twice at the same token,
   `clearMode(MODE_FUNCTION_NAME)`. The tokens are held as `antlr::RefToken`
   (a raw `Token*` compare could see a freed and reused address). The new markup
   is a recovery, not proper C++; for all 22 recovered files the token texts
   give back every non-blank source character in order (M).
3. **Java srcML#2361 needs no fix.** Upstream fixed it in 6fb134892 (PR #2396),
   which d38271916 contains. The 8 denylisted Java blobs finish in 0.02-0.16 s
   in both builds with identical output (M).

## 3. Byte-identity regression (8,492 blobs; only libsrcml differs)

Set: random foxhound 1,973 + linux 1,161 + sapmachine 1,296 + tengine, doris and
catch2 749; all 1,524 unique NSS blobs at foxhound HEAD; all 449 sonic-pi
boost/hana headers; 1,123 files with adjacent literals; 251 with a macro before
`template`; the 12 denylisted blobs. 688 blobs were not compared (their repos
were cleaned up mid-run: 644 ppsspp, 44 linux).

- 8,454 identical, including all 5,179 random blobs.
- 22 never finished before: 17 hana, 4 denylisted `.h`, and sapmachine
  `continuationFreezeThaw.cpp` (old >900 s, new 0.25 s).
- 12 corrections (cper.c, acpi_extlog.c, ghes.c, mips io.h, 3 x86 selftests,
  qlcnic_ctx.c, nouveau bios base.c, hotspot unsafe.cpp, 2 aiohttp files); for
  each, the old build on the spaced copy equals the new output.
- **4 not corrections:** sqlite3.c copies (libsqlite3-sys, sqlcipher, NSS
  lib/sqlite, third_party/sqlite3). A separate, older srcML defect breaks both
  builds there: an `#error "...\` string continued over a backslash-newline
  (line 14259) leaves an unbalanced quote, so both outputs are wrong from that
  line on, and the fix splits that wrong text differently. With those quotes
  blanked at the same offsets, old and new are byte-identical on all 4. **Open
  decision for the user:** accept these 4 as harmless, or fix the `#error`
  defect too.
